## Clock and all 32 Body phases

The original unpaused writer selects the 32-long rate array `$7AEA..$7B6A` and the 32-long phase array `$575A..$57DA`, then adds each rate to its paired phase once per tick. The preceding `$70BC` pause branch skips the additions. The same unpaused section increments long logical tick `$53094`; clock fraction subtraction follows the phase additions. The independently recomputed writer hash for `$53144..$53164` is `9b8b8e70e1f3be5c1c769dc0e5abbabe6a1e467645a77c8bd1fb0794bea6715f`. [Clock ownership](mercenary-iii-tourcraft-clock.md#clock-ownership-and-arithmetic), [original phase inventory](mercenary-iii-tourcraft-state-inventory.md#mutable-owners-to-serialize)

Executed checks establish:

- Every one of the 31 named Body rates equals its promoted `system.bodies[i].rate`; the final unnamed array entry has rate zero. The original complete rate array hashes `b7b8587d50d055297e2c781b16e34cd724c6c06b87448adf4c275a42f7932c9d`.
- All 32 coherent opening phases equal `29 * rate[i]` modulo `2^32`, and opening `$53094` is 29.
- Across all fifteen natural R7 captures, each of the 32 phases equals `rate[i] * long($53094)` modulo `2^32`: **480 comparisons, no difference**. Their logical counters range from 18,729 at `v23450.ram` to 30,277 at `v35000.ram`. This includes observed surface/space/arrival changes while rates remain the admitted defaults; it does not prove arbitrary pause/rate histories.

The old I2 sky origin is different: its opening METIS phase is 39,648 (`42 * 944`), whereas the coherent promoted R7 opening METIS phase is 27,376 (`29 * 944`). Both have clock accumulator 672. The old sky capture is separately identified by `openingRamSha256=5bd00eb63ba83b68ae32992fc201af11047c985948517a4e6f16c0422d8c3aa0` in [world.json](../../payload/dion/world.json). That RAM artifact was not located during this audit; the promoted R7 opening must not be relabelled as that capture.

For a **legacy-aligned expanded reference** whose New Game preserves the old METIS phase, all default phase seeds can be defined explicitly as `R7initialPhase[i] + 13 * rate[i]`, giving the bounded source-only rule:

```text
bodyPhase[i] = (R7initialPhase[i] + (13 + source.snapshot.tick) * rate[i]) mod 2^32
             = ((42 + source.snapshot.tick) * rate[i]) mod 2^32
```

This is a compatibility alignment of the reference's initial phases, supported by the original common writer; it is **not** an executed claim that the missing old opening RAM contained those exact 32 values. Require equality at METIS index 15 with the retained `source.snapshot.phase`, use integer arithmetic with sufficient precision, and preserve that saved field. A source which fails the check has not established the required unpaused legacy writer history. Preserve saved clock accumulator/day/seconds and elapsed remainder independently; the thirteen-phase-tick alignment is not permission to add thirteen ticks to its clock. The ordinary legacy tick writer has no original-pause/rate control, and TOURCRAFT/space rate writers are unreachable through the I2 interface. New original pause and rate owners are consequently `pause=0`, `rateExponent=6`, `step=32`, `period=1600` under that domain, rather than inferred from rounded panel time. [I2 tick owner](../../web/src/dion/session.ts), [rate writers and exponent](mercenary-iii-tourcraft-clock.md#clock-ownership-and-arithmetic)

## Pilot and face animation

The old source already serializes `driver.selector`, `driver.index`, `driver.remaining`, `driver.profile` and pending `narrative.cabin`. These are distinct from newly added face-token owners and must be preserved. The original pilot descriptor/head binding must follow actual Occupancy (taxi pilot 263, TOURCRAFT pilot 279), rather than opening seeds. A pointer adapter for the old driver's index still needs to specify whether its index denotes the currently read duration or the next unread byte: the current old walker increments the index when fetching the next duration and normalizes termination to selector/index zero. A normalized inactive browser owner need not preserve a stale original pointer unless a future reader can observe it, but that omission needs reader justification. [Old driver writer](../../web/src/dion/session.ts), [original head selection/sequences](mercenary-iii-tourcraft-presentation.md#cabin-pilot-lettering-and-panel)

The selected message character at `$723C` is a **byte**, rather than a word-wide profile latch. Scrolling `$53366` reads the next glyph from `$7232`, stores it at `$5336E`, and final idle `$53418` clears it. Original head selection `$544D2` tests that byte while busy. The source's display-mode word `$723E` is separate: positive description continuation writes 2 at `$55A86`, and final idle clears it at `$53402`. A source-reference scan across the original code range `$4BBD0..$5C000` found those two writing references. The packed script path `$52D58` and external ID helper `$55B2A` decode their text without changing that mode. Reachable single-row early taxi messages consequently keep mode zero when no positive continuation is admitted. This writer closure gives a concrete route to deriving mode from validated message eligibility, but does not make the currently scrolling glyph constant over a busy interval. [Message/continuation boundary](mercenary-iii-tourcraft-boundary-controls.md), [original message grammar](mercenary-iii-taxi-content-presentation.md#messages-and-scripts)

For the faces, the independently inspected reader confirms the exact conjunction:

```text
alternate = messageBusy && word($723E) == 0 && (byte($7272) & 0x20) != 0
```

Each frame advances only the selected cursor. Base lengths are 31/21 and alternate lengths 45/31 for `$A1`/`$A5`; the unselected cursor survives. Each noninitial output is the selected sequence's glyph at the resulting cursor, including reset-to-zero on NUL. Opening output words are space+NUL (`8192`), and all four indices are zero. After one ordinary base-selected update, they are **indices 1/1**, outputs C/P; they cannot remain opening blanks. The full reader's recomputed hash is `e9283e4da249ee8ccf4cdbdac424cda73d8d1cef4f2ed17184a4842df14dbaea`, matching R7. The caller runs independently of model visibility. [Caller and writer probes](mercenary-iii-tourcraft-presentation.md#cabin-pilot-lettering-and-panel), [served exact sequences](../../payload/dion/tourcraft/presentation/programmes.json)

At original loop top the observed static order is threshold `$5A41A`, input `$5A448`, VM `$5A474`, face animation `$5A47A`, then mode-specific service/movement/admission. A message emitted by the VM affects the same frame's face selection; an admission-created ID emitted in the later mode-specific section affects the next invocation. A reduction which counts only each message's nominal duration without distinguishing its creation phase can therefore shift the cursor. Start/reentry ownership remains separately governed by [the accepted atomic contract](mercenary-iii-tourcraft-followup.md#accepted-timing-clarification-and-confirmation-probe).

Consequently, if `N` animation invocations have occurred and `A` of them selected alternate, a replay can derive the four cursor values:

```text
A1.base = (N - A) mod 31; A1.alternate = A mod 45
A5.base = (N - A) mod 21; A5.alternate = A mod 31
```

For `N>0`, output additionally needs the last selection; for `N=0`, keep the initial blank. The saved global frame count gives `N` only under a reference whose initial animation phase and subpass ownership are defined. The old source has no explicit `A` or last-selection history, and its narrative has no original `$723E` owner. The current busy/flags/text/age describe the saved message, not the cumulative sequence selection during earlier messages. Taxi helpers themselves clear/set flag 13. Thus "pre-election, use base animation only" is not supported by the source writer closure. A source-only derivation needs additional reasoning over message occurrences, their modes and script history, or an explicitly eligible canonical prefix. The later [early experiment](mercenary-iii-tourcraft-early-initialization.md#the-early-collision) demonstrates lost last-selection information for identical old sources; an observable-reader or omission proof remains necessary. [Old narrative owners](../../web/src/dion/script.ts), [closing helpers](../../payload/dion/scripts.json), [conservative state inventory](mercenary-iii-tourcraft-state-inventory.md#mutable-owners-to-serialize)

The natural R7 captures corroborate the warning: already at `v23450.ram`, before TOURCRAFT admission and with request/timer zero, `$A1` has base/alternate indices **29/21** and `$A5` **20/3**. Both alternate cursors therefore changed during the early taxi history; current scene visibility and empty campaign request are insufficient reasons to seed them from the opening. This is a concrete counterexample to freezing newly introduced face state, using an actual early original-machine capture. It is not a pair of identical I2 source records.

### Finite early message arithmetic

An additional executed pinned-I2 observation replays all 33 prefixes, wrapping the narrative frame call only to count `busy && flags[13]` after its ordinary VM work and before service/admission. A second observational wrapper logs successful message requests, distinguishing VM requests from later external IDs; it preserves each request/frame method's result and never restores a fabricated snapshot. With early ordinary mode zero, all 33 counted values equal the sum of completed request contributions plus the current partial interval. This checks a finite prefix model; it does not yet derive the request list from the saved source alone.

For these prefixes, a VM message request is seen by faces on its creation frame. It starts at age -1 and remains busy while age is below its hold. At eleven ticks per frame its full contribution is `1 + floor(hold/11)` when flag 13 is true: hold 200 contributes 19. External boarding/arrival ID messages are created after faces, last 251 ticks from request to idle, and contribute 22 later animation invocations when flag 13 is true. Requests with flag 13 false contribute zero alternate updates. Script execution is blocked while a message is busy, so these selected script requests do not change flag 13 during the interval. The current partial contribution needs age and whether creation preceded or followed the face call, not merely current busy. [Pinned frame/request ownership](../../research/mercenary-iii-st/scripts/taxi-source.ts), [old message tick](../../web/src/dion/script.ts)

The completed opening contributes **228** alternate updates. Ordinary accepted boarding adds **22**. The completed solicitor routine adds **38** (two selected hold-200 messages), and its accepted arrival adds **22**, giving **310** at `sol/exit-post`. The completed spaceport routine adds **304** (sixteen selected hold-200 messages); its arrival ID is refused, giving **554** at `sp/exit-post`. Other representative observed counts are `sol/mid-reveal=0`, `sol/waiting=228`, `sol/selected=250`, `sol/scroll=251`, `sol/clear-pre=288`, `sol/descending=293`, `sp/driver=251`, `sp/turn-pre=311`, `sp/turn-post=312`, `sp/travel=408`, and `sp/clear=544`. No-start stationary controls remain 250. [Exact control generator](../../web/test/dion-controls.ts)

A possible source-only reduction would identify the completed script-message prefix from saved PC, return stack and consumed routine availability, then subtract that request count from message serial to count successful external IDs. Those serialized facts may be sufficient for the finite matrix, but that is a construction to verify, not established by the observational replay. A source-only proof must also account for shared helper PCs, interrupted epilogues, accepted/refused reboarding and partial-frame last-selection ownership. Equal cumulative alternate count alone does not guarantee equal current output: the last frame may have selected different sequences even when both present messages have since become idle.
