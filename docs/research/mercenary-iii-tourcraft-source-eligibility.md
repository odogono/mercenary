## Cross-field checks owned by historical writers

Let `T = snapshot.tick`, `F = floor(T / 11)`, and use exact integer arithmetic for products before taking a modulus. The coherent old opening has clock accumulator 672, seconds/day zero, step 32, refill 1600, frame counter 1, METIS phase 39648, and rate 944. [Pinned opening data](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/payload/dion/world.json), [pinned constructor/tick/frame writers](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/session.ts)

```text
Q(T) = 0                                      when T < 21
       1 + floor((T - 21) / 50)                otherwise
clock.accumulator = 672 - 32*T + 1600*Q(T)
clock.seconds     = Q(T) mod 86400
clock.day         = floor(Q(T) / 86400) mod 65536
frame             = F
frameCounter      = (1 + F) mod 65536
phase             = (39648 + 944*T) mod 2^32
```

These equations follow from subtracting 32 each tick and refilling at accumulator **at or below zero**. They are not `floor(T / 50)`: the first second is tick 21. In particular, a forged late clock with an early tick is refused even if all individual numbers are decoder-valid. Clock seconds alone cannot identify elapsed history after day rollover. `snapshot.day`, the daylight flag, is recomputed only at atomic frames; compare it with the pinned sky function at phase `(39648 + 944*(11*F)) mod 2^32`, not the saved partial-frame phase. ## Total source-only reachability relation

Define supported histories over the actual frozen I2 transition interface, with no injected snapshots, clock/pose/VM assignments, TOURCRAFT boarding, Body transfer or foreign content:

- `press(a)` for `a` in `activate, star, plus, minus, board, leave`;
- set a supported Movement Intent with fields `look,pitch,running,strafe,turn,walk`, finite binary64 axes in `[-1,1]`, and boolean `running`;
- `advance(d)` with finite nonnegative binary64 seconds, preserving each call and its arithmetic;
- capture the current old record, encode it through the historical JSON Save/Resume writer, and restore that **genuine encoded capture** through the corresponding historical reader/constructor, as ordinary Save/Load or Session Resume can do.

This deliberately covers both production calls of `1/60` from the old fixed-step Browser Shell and the retained research API recipes using `1/50`, `11/50`, `64/50`, and other ordinary elapsed calls. It does not redefine all natural input as a fixed keyboard alphabet, integer frames, or one taxi journey. The six old actions include calls, retries, no-start waiting, rejected Leave, multiple trips, returning to a former cell and arbitrary free waiting. [Pinned interface](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/session.ts), [production fixed-step bridge](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/shell/clock.ts), [production control adaptation](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/controls.ts), [retained recipes](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/test/dion-controls.ts)

For source `S` with tick `T`, form the following finite graph:

1. Begin with the pinned fresh session, including its immediately started `$19` routine and freshly selected candidate.
2. A node contains the complete private historical simulation state, **unclamped** private remainder and current intent. Omit only the append-only host sound-write queue, which has no simulation reader; keep serialized sound state. Distinguish node state from `captureResume()`, which clamps negative remainders and omits live intent.
3. Add each supported action, intent and elapsed transition. Discard transitions that exceed tick `T`; an elapsed-call evaluator may stop when it would perform tick `T+1`. Compute the full zero-tick closure, deduplicating identical nodes rather than limiting the number of key presses or sub-tick calls.
4. Add a self-capture/restore transition only using the node's genuine `captureResume()`, historical Save/Resume JSON writer and corresponding pinned reader/constructor. Require that genuine encoded capture to pass the historical reader; a refused capture supplies no restore edge. Retain JSON numeric projection, candidate rescan and remainder clamping. Restore starts with idle intent. Passing an unencoded structured clone directly to the constructor is not this edge: JSON turns any serialized `-0` into `0`. No fabricated decoder-valid state is an edge.
5. Accept terminal nodes at tick `T` whose **entire captured record, after the historical JSON writer's projection**, equals `S`: all nested values, array order, pixels, candidate, phase and remainder. Metadata does not participate. Keep signed zero distinct in private node keys and input operands; JSON serialization turns an internal `-0` into `0`, so a bitwise comparison of an unencoded capture is not the encoded-source comparison. This does not permit dropping fields or rounding an ordinary positive remainder. [Pinned JSON writer](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/save.ts)

The effective selected history of a Load of an earlier genuine capture is its saved prefix followed by the later continuation; discarded play after making that Save does not contribute to its reference. This reduces ordinary branching/reloading to the genuine-capture edge without adding arbitrary restored states or requiring monotone wall time. New Game simply supplies another fresh root. [Pinned restore constructor](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/session.ts), [Save/Resume readers](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/resume.ts)

The graph is finite for each decoder-valid finite `T`: binary64 inputs/private numeric states have finite representations; at most `floor(T/11)` VM/frame calls bound script stack and message serial; immutable content bounds strings, pixel arrays, available IDs and doors. Zero-tick input loops can therefore be saturated rather than searched to an arbitrary depth. This is a termination argument for a **definition**, not a claim that enumerating every floating-point intent and elapsed value is practical. An efficient symbolic/constraint solver may implement the same relation, but a timeout is an unresolved eligibility result, not evidence of unreachability.

Let `H(S)` contain **all finite operation words** ending in a matching terminal node, including paths around historical zero-tick cycles. Historical-node deduplication is valid for deciding reachability, but does not identify histories for expanded comparison. No expanded-state equivalence is inferred from identical old nodes. The total source predicate is:

```text
eligibleSource(R) = exactRawSchemaAndIdentity(R)
                && historicalDecoderValid(R)
                && writerCrossFields(R)
                && H(decodedState(R)) is nonempty
```

Every supported naturally written record has its own path as a witness. A forged record that passes the cheap checks still needs a full path. This defines the full admission domain; **the finite test matrix and necessary cross-field checker are not its implementation or a replacement allowlist**.

### Direct decision procedure and safe reductions

The graph definition has a direct, terminating source decision procedure. Enumerate the finite operation alphabet above, including each permitted binary64 operand, in its specified order. Starting at the fresh root, evaluate each outgoing operation with the actual historical arithmetic and intern its resulting complete private node. Queue a node only on its first visit. For `advance`, stop before performing a tick greater than the target and discard that edge; a call which cannot return within the target never supplies a terminal capture. Include zero-tick operations and genuine-capture restore operations in the same queue. Stop with a witness on the first complete source match, or refuse only after the queue is exhausted. No bounded key-press depth, keyboard-only intent approximation, guessed elapsed-step alphabet or timeout can turn an unexplored source into an unreachable one. [Pinned operation and capture writers](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/session.ts)

Finiteness here concerns mathematical termination rather than acceptable migration latency: even one analog axis has an enormous finite domain. The pinned reader bounds target tick by `Number.MAX_SAFE_INTEGER`; frame-local work bounds stack growth and accepted message requests by that target. Press and intent assignment do not execute the VM, advance the sign, emit a message or change simulation tick. An arbitrary number of such zero-tick calls therefore adds no unbounded owner. Restore rescans the candidate and resets live intent but does not increment a message serial or animation cursor. The host sound delivery queue is the sole append-only collection excluded from node identity, because neither simulation nor capture reads it. These facts justify finite saturation over this exact interface; they do not justify deduplicating distinct expanded histories. [Pinned numeric admission](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/restore.ts), [pinned narrative writers](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/script.ts)

Canonical selection needs an additional finite graph key: the entire successful departure vector accumulated so far. Saturate `(historical node, departure vector)` pairs, retain all accepting pairs and choose their least vector under the order below. Then choose the shortest path to an accepting pair carrying that vector, with operation order deciding equally short paths. A shortest-path search may retain one shortest lexicographic path per **pair**. Retaining only the apparently best departure prefix per old node is invalid: prefix-first lexicographic order is not preserved by appending a later departure. For example `[] < [10]`, while after a common later departure `[20] > [10,20]`. Because departures occur at strictly increasing global frames, vectors have length at most `F` and finite entries; this product graph remains finite.

The research-only [`searchTaxiReferenceGraph`](../../research/mercenary-iii-st/scripts/taxi-reference-graph.ts) now executes this product-graph algorithm, including both operation-word tie breakers. Its adapter must supply immutable complete private nodes, a key that preserves their transition behavior, every supported outgoing operation in strict total operation order, and a complete encoded-source match predicate. One edge represents one supported operation, even if an `advance` crosses several frames and departures. Its departure entries are **pre-Start frames in `[0,F-1]`**, not consuming frames or ticks. The queue explores words by length and then operation order; first visitation of a pair therefore retains its shortest lexicographic word. Appending the same continuation preserves those word tie breakers. It does not preserve departure-prefix order, which is why distinct vectors stay in distinct pairs. Accepting nodes remain in the zero-tick closure; encountering a source match does not end the search.

Only exhaustion of the supplied graph returns its least reference or `unreachable`. A state budget returns `unresolved`, together with any already observed complete-source witness as **existence evidence only**. No cutoff selects that witness as canonical. The discovered-pair count includes queued pairs whose outgoing edges may still be unexplored. Ordered-edge and departure-bound checks reject a malformed adapter. These runtime checks do not prove that its private-state key, operation alphabet or terminal predicate is complete.

The [regression](../../web/test/dion-reference-graph.test.ts) independently enumerates all 256 source classes over a synthetic three-frame graph, verifies merged departure prefixes, zero-tick cycles, shortest/lexicographic ties, multi-departure elapsed edges and cutoffs. This executes the graph algorithm, **not the historical I2 graph adapter**. A restricted recipe graph would choose only that graph's reference; it cannot certify full `H(S)`, natural-source refusal, early exactness or global minimality for the retained collision ledgers. The historical operation enumeration/private-state adapter and practical reductions remain unimplemented. [Independent proof review](mercenary-iii-tourcraft-r8a-proof-review.md)

A second, executable selection procedure is [`selectTaxiCanonicalDepartureSchedule`](../../research/mercenary-iii-st/scripts/taxi-canonical-reference.ts). It takes the capture frame and a reachability oracle for the **same complete old source class**. With departure prefix `p`, first ask whether any complete matching history has exactly `p`; if yes, stop. Otherwise ask whether a complete matching history extends `p` with a next pre-Start frame at most `F-1`. If no, the empty prefix establishes unreachability; for an already proven feasible prefix that answer would be inconsistent. If yes, binary-search the least next frame using that monotone existence query, append it, and repeat. Every query concerns a complete source match, not merely a prefix that could execute. At most `F` departures and logarithmically many queries per departure suffice. An unresolved answer at any step returns the exact unresolved query; it selects no reference and proves no refusal.

The prefix test is what makes this procedure correct for no departure and repeat trips: a feasible terminal prefix precedes every extension; otherwise all accepting extensions share a least feasible next value, and the same argument applies recursively. It avoids enumerating every departure vector but does not solve the inverse historical input problem hidden in the oracle. After finding the least vector, the product-graph shortest/lexicographic path rule above still chooses the operation word. An oracle implemented by a finite list of measured controls is valid only for that explicitly finite family, never for `H(S)` generally. The regression compares this algorithm with exhaustive sorting for **all 256 possible history classes over three frames**, tests absent/repeated/interrupted/returned departure families, safe-integer bounds and unresolved results. The retained late audit additionally runs the selector over all three complete matches in its calibrated fixed-recipe family and requires the same earliest candidate. Neither test supplies a universal source oracle.

An optimized solver may collapse operations or use symbolic input intervals only after proving those reductions preserve complete old captures, successful departure vectors and the expanded reference effects. The clock/phase equations and frame cadence are safe pruning constraints because they follow from every writer. The single-trip wait congruence, current message PC and saturated age do not have that status for arbitrary histories.

### What the source fixes and what it forgets

| Saved evidence | Writer-derived information | Information not supplied by that field alone |
| --- | --- | --- |
| `tick`, `frame`, `clock`, `phase`, `frameCounter` | Exact elapsed simulation ticks, completed atomic frames, clock rollover and phase recurrence. | Input times, taxi departure times, accepted boarding times and the number of face updates choosing each sequence. |
| `narrative.wait` | Tick count since the last `$02` reset, modulo 65536. | Which reset occurred, its absolute tick, or which earlier routine/reset histories share this residue. |
| `available`, `pc`, `stack`, flags | Current routine availability and interpreter state, including active shared helpers. | A list of completed message intervals or every earlier external request; shared helper PCs identify no unique calling history by themselves. |
| Message `serial`, `text`, `age`, `busy`, `hold`, `scrollsOut`, pixels | Number of accepted requests and complete current retained display state. An active message may constrain its creation tick. | The selected flag value of every earlier accepted message. After idle, age stops changing; it is not an absolute completion timestamp. |
| Taxi state, pose, admission, pending input and candidate | Complete current service/admission state and the next consumed action. | A unique itinerary, count of earlier refused requests, or unique boarding frame. |

These distinctions follow from the archived wait reset/increment, request refusal/serial increment, idle-age retention, routine removal and frame/input writers. In particular, message serial plus consumed availability may help a solver count completed requests, but it cannot be treated as a proof that all those requests selected the same face sequence. An external accepted ID occurs after that frame's face call; a VM message occurs before it. A helper can change flag 13 between messages. An exact early proof must resolve those intervals under all matching histories, rather than infer their cumulative selection from the final flags. ## Exact early domain

### Complete source/reference rule before the first tick

[`taxiZeroTickReference`](../../research/mercenary-iii-st/scripts/taxi-zero-tick-reference.ts) decides complete historical reachability and the globally least operation word for the entire **tick-zero** subdomain. Apply the candidate gates above, require `snapshot.tick == 0`, and compare the **whole decoded source snapshot** with the historical fresh capture after JSON writer projection, substituting only the source's pending action and remainder. Any other difference is refused at `snapshot.snapshot` with `zero-tick state differs from the historical opening`. An elapsed source returns `outside-domain`; this is not a refusal of later ordinary play.

This domain is not an allowlist of opening checkpoints or tested remainders. `press` only writes pending input; assigning intent writes a private owner omitted from capture; `advance` without a tick only adds remainder. The tick/frame writers own every other mutable serialized field. A genuine tick-zero encoded restore preserves this state and resets live intent; candidate reconstruction is stable because fresh pose, residents, sign, driver and frame state have not changed. Effective histories that reload an earlier tick-zero capture reduce to its saved prefix under the general relation above. Therefore every reachable tick-zero source has exactly the required historical snapshot shape. [Pinned press/advance/constructor/capture](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/session.ts)

Conversely, every source with that shape and admitted remainder `r` has a natural witness: press its nonnull pending action, if any, then call `advance(r)` if `r > 0`. Adding a positive binary64 `r` to fresh zero produces that exact value, and the admitted tolerance check prevents a tick. No successful taxi departure is possible, so every matching history has the empty departure vector. Nonnull pending requires at least one press; positive remainder requires at least one advance. The witness reaches that lower bound on word length, and press sorts before advance when both are required. Its positive elapsed operand is uniquely `r`. No intent assignment, zero elapsed call or genuine restore can improve the word. Thus this is a complete reference selection within the full supported interface for this subdomain, not selection among a supplied witness list.

The [regression](../../web/test/dion-zero-tick-reference.test.ts) executes **35 natural sources**: null or any of the six pending actions, crossed with zero, the least positive subnormal, `1e-12`, `1/60` and `1/50 - 2e-12`. Each source includes extra ordinary intent/zero-elapsed calls that the minimum word omits, independently replays the selected word, passes genuine encoded Save/Load and metadata-independence comparisons, and matches complete historical state and ordered PSG writes through **600 later frames** with equal idle intent: **21,000 future frame comparisons**. The five tested remainders exercise the rule; they do not bound its positive binary64 domain. A forged tick-zero heading is a separate decoder/candidate-valid synthetic refusal. Separate raw negative-zero tick/remainder probes exercise the writer-projection gate and preserve their input literals. [Source boundary regression](../../web/test/dion-source-eligibility.test.ts)

This proves full **historical** source admission and global reference-word selection at tick zero. It does not construct or compare every added expanded owner, or certify the complete `P(E)` predicate below. All 33 retained controls have elapsed ticks and remain outside this completed subdomain. Their source-class classifications and the general early/late inverse solver remain required.

### Complete expanded meaning

The first elapsed second reaching 32,400 is tick **1,619,971**. Threshold-before-input runs only at atomic frame tops; the first possible election reader is frame **147,271**, tick **1,619,981**. Thus ten partial-frame ticks with `clock.seconds == 32400` still precede the first admitted campaign reader. A later day with seconds below 32,400 is not pre-election. Derive the boundary from the pinned clock and cadence plus R6's threshold ordering, not a decoder's seconds field alone. [Clock writer above](#cross-field-checks-owned-by-historical-writers), [R6 scheduler recovery](mercenary-iii-tourcraft-campaign.md), [independent threshold model](../../research/mercenary-iii-st/scripts/taxi-history-model.ts)

For each matching witness `h`, let `E(h)` be expanded execution from New Game under the accepted initial alignment and cadence, applying the same ordered ordinary inputs. A `captureRestore` edge takes a genuine **complete expanded** capture and restores that capture through the eventual #736/#737 restore contract, including remainder clamping, idle live intent, candidate reconstruction and output rebuilding before first draw. It does not migrate the intermediate old record again or install its old cash/VM over campaign state. This defines the required reference operation; that expanded restore contract is still a dependency, so its semantics are not claimed implemented here. Histories without restore edges use uninterrupted expanded execution. Define `P(E)` to retain every future-affecting serialized owner and all first-frame/panel/event observables, identifying only state that #736 actually proves is rebuilt before **every** reader. Live Movement Intent is supplied equally when continuing; held controls are not saved owners and do not participate in source equality. Under the [accepted #736 contract](mercenary-iii-tourcraft-face-rebuild.md#accepted-serialized-field-and-writer-contract), face output words are derived from the shared retained `faceSelection` tag and both cursor pairs. Compare outputs after that nonadvancing rebuild; the tag and all four cursors stay in `P`.

The exact early predicate is:

```text
early(S) = eligibleSource(S) && T < 1619981
exactEarly(S) = early(S) && | { P(E(h)) : h in H(S) } | == 1
ambiguousEarly(S) = early(S) && | { P(E(h)) : h in H(S) } | > 1
```

## Canonical reference rule for all history families

Under [ADR 0070](../adr/0070-use-canonical-expanded-history-for-ambiguous-early-taxi-records.md), apply the same ordering to ambiguous early sources as to the late domain already authorized by ADR 0068. Where every matching history has the same retained expanded meaning, that meaning is the exact reference; choosing a representative input word must not change it. The full early classification and canonical comparisons remain unexecuted.

For each matching witness, record **successful old taxi Starts**, including the input frame before the service pass changes `taxi.start`. Rejected presses, card calls on foot and a pending Start not yet consumed are not departures. Each successful departure is labeled by its consuming global frame; its pre-Start frame is one less, matching the retained single-trip convention. There are at most `F` successful Starts because input is consumed once per frame. [Pinned handleInput/frame order](https://github.com/odogono/mercenary/blob/e4cba434069ca1fbec6e72b3a99cbf775f1663c4/web/src/dion/session.ts)

Choose a matching witness by the following total order:

1. Lexicographically smallest finite vector of successful pre-Start frame numbers, with a proper prefix sorting before its extension. This chooses the earliest first departure among nonempty schedules, then the earliest second, and so on; equal shared departures favor a shorter schedule. The empty no-departure schedule sorts before every nonempty one. This is the ordinary prefix-first lexicographic rule implemented by `compareTaxiDepartureSchedules` (which records equivalent consuming ticks).
2. Among equal departure vectors, shortest effective supported operation word, including genuine-capture restore edges. Zero-tick loops are therefore never needed as tie-breakers.
3. Among equally short words, lexicographically smallest operation word: opcode order `press < intent < advance < captureRestore`; press order `activate < star < plus < minus < board < leave`; intent fields ordered `look,pitch,running,strafe,turn,walk`, false before true; numeric values in increasing numerical order with `-0` before `+0` for an otherwise equal binary64 pair. Compare finite numerical operands by their exact binary64 values, not locale/string order.

The least departure vector exists because its entries range over a finite bounded set. For that vector a minimum finite word length exists, and for that length the finite alphabet has a least word. Every selected history must still reproduce the **complete old source**. Equal old source state therefore selects one reference independently of original departure, slot, descriptions, storage timestamps or current wall time. Earlier API-call chunking is retained by the final tie-breaker; an implementation cannot coalesce its calls before proving that rewrite preserves both source and reference.

This order applies to histories with no trip, multiple trips, repeat boarding, changing destinations, returning to prison, rejected requests, and genuine restores. It does not impose a latest boarding time. It generalizes the retained earliest-departure result: inside that fixed single-trip recipe, the departure vector has one entry and the known candidates are **16,156**, **81,692**, **147,228**, so **16,156** wins. The fixed-family wait congruence and calibrated `+484` reset offset may prune those candidates; neither is a general invariant for other routines, message timing or trip schedules. [Single-trip arithmetic and three complete matches](mercenary-iii-tourcraft-canonical-reference.md#candidate-derivation-and-exact-match-boundary)

This is a documented reference rule with an executed general departure-ordering algorithm and a finite product-graph search implementing its shortest/lexicographic operation-word tie breakers. The historical graph adapter/source oracle remains a specification; universal reachability execution and independent expanded reconstruction remain unproved. A source-only constructor must advance the selected expanded history from its pinned initial facts, applying campaign changes when its history requires them. Selecting a final wait residue, installing a fixed cash/flag tuple or postponing past campaign work until Load does not implement this rule. [ADR 0068](../adr/0068-reconcile-known-taxi-saves-with-expanded-campaign-history.md), [owner construction boundary](mercenary-iii-tourcraft-state-inventory.md#remaining-proof-boundaries)
