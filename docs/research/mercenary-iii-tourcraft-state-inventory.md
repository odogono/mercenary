The inventory separates mutable owners that a Save Snapshot must retain from immutable dependencies and derived work. It extends the taxi inventory through resident-13 playback, System space, TOLOSA arrival, ordinary Leave and the connected default campaign/passive OBSERVER closure. It neither introduces runtime code nor establishes browser Save/Session Resume equivalence.

The conservative disposition is **serialize newly mutable owners until their omission or reconstruction has been proved against uninterrupted futures**. A RAM field remaining unchanged in early flight does not establish that it is immutable during freely permitted waiting. Whole-machine restoration preserves more than a portable Save Snapshot; its success does not prove this inventory sufficient. The accompanying R8 expanded-state work owns those comparisons and the final completion decision. [ADR 0073](../adr/0073-drop-pre-release-prototype-save-migration.md) retires old prototype migration; it does not relax this inventory.

## Current schema gaps and reuse

The existing [Dion Snapshot](../../web/src/dion/session.ts) owns the taxi world, one METIS phase, a fixed ordinary clock, narration, pilot, sign and sound. [Its strict reader](../../web/src/dion/restore.ts) is useful infrastructure but cannot admit the expanded flight: there is no craft/space/playback/Body-context/actor/face state, and clock admission is bounded to the taxi accumulator. [DionNarrative](../../web/src/dion/script.ts) stores available IDs instead of original availability bytes, replaces the return stack on start, refuses every active start, clamps its unused timer to zero and interprets the target as an ordinary script number. The admitted campaign requires the title-local extensions identified above. Constructor `selectCandidate()` currently recomputes a restored candidate; the expanded boundary contract must preserve the previous-frame candidate when input/admission depends on it. These are code-inspection findings, not claims that existing taxi controls fail.

Reuse assessment follows [R6's exact matrix](mercenary-iii-tourcraft-reuse.md#reuse-matrix-and-implementation-handoff): extract/use pure packed arithmetic, `craftPass`, `spacePass`, support/box predicates and suitably bounded landing mathematics with Dion-owned data. Preserve Dion's playback decoder, service-before-collision order, unrotated nearest-Body ranges, automated landing rotation exception, frame reentries, clock, script and actor pool. Damocles [CraftState/SpaceState](../../web/src/damocles/craft.ts) are useful checklists for numeric carry fields; their original addresses and defaults do not establish Dion state identity. Damocles [encounter pool](../../web/src/damocles/encounter.ts) has different slots and no on-foot programme, so direct pool/schema reuse is unsupported.

Reuse the established own-title `DionResumeRecord` capture/strict-reader pattern and Browser Shell Save/Resume envelope/storage separation. Shared [YM/programme walkers](../../web/src/sound/stProgrammes.ts), [sky](../../web/src/damocles/sky.ts) and [stars](../../web/src/damocles/stars.ts) provide recovered mathematics/backend support; sound progression and each frame's Dion view selection remain title-owned. R6/R7 prove enough correspondence to assess these boundaries, not a generic cross-title Gameplay Session or a universal Save schema. A consequential shared extraction still requires the documented ADR discipline.

## Remaining proof boundaries

This audit runs source/capture hash checks and targeted reader inspection only. It runs no emulator continuation, RAM omission experiment, new whole-machine restore comparison, browser Save/Session Resume comparison or migration test. Concrete downstream obligations are:

- Compare uninterrupted/restored futures on both sides of pending B/admission/start, surface→space reentry, arrival hold/request/Body setup, each frame-byte wrap, contact, record 911, Leave 927 and first on-foot arrival, with neutral and turned cabin views. Retain the first frame/panel and ordered sound/message outcomes, not merely the endpoint.
- Exercise connected campaign queues, `Close`/return nesting, timed target overwrite, active-dialogue admission and cash clearing, passive request override, space suspension, Body reset/replacement and actor departure/expiry. Empty early-flight queues cannot stand in for these reachable futures.
- Implement the [R8b field-level representation and validation contract](mercenary-iii-tourcraft-snapshot-fields.md) for numeric/actor/sound rows, including reference bounds, cross-field consistency and excluded alternative flags/models/programmes. Original raw addresses identify readers; they are not a completed browser schema. Justify each new reconstructible candidate by a restored-future control or keep it serialized.
- Keep one coherent initial gameplay capture and provenance for every New Game seed. Neither runtime state nor immutable dependencies may be seeded from Catalogue incidental mutable observations. Save progressed owners directly and restore them from the complete expanded snapshot.
