# Mercenary III TOURCRAFT: restore futures and migration gate (R8)

Research for [#709](https://github.com/odogono/mercenary/issues/709), 2026-10-02, consuming [R6](mercenary-iii-tourcraft-playback.md) and [R7](mercenary-iii-tourcraft-promotion.md). This is a persistence specification and original-engine research handoff, not a runtime or codec implementation. **The compatibility priority is now accepted:** under [ADR 0068](../adr/0068-reconcile-known-taxi-saves-with-expanded-campaign-history.md), valid late I2 records must match expanded campaign history even where this changes saved cash/script state. I2 admits long-waiting records whose retained fields differ from that history. The [migration audit](mercenary-iii-tourcraft-taxi-migration.md) supplies the exact source identity, validator and reproducible counterexample. Do not silently reset those records or replace migration with blanket taxi-Save refusal. #709 and I4 still require deterministic reconstruction and independent browser proof, using the accepted canonical reference for ambiguous late sources.

The [state inventory](mercenary-iii-tourcraft-state-inventory.md) owns the reader/writer and reconstructibility audit. The original restore comparisons below establish finite whole-machine continuity. Neither static inventory nor restoring an emulator machine proves that an independently authored browser Save Snapshot contains every owner.

The [late-history ambiguity comparison](mercenary-iii-tourcraft-history-ambiguity.md) tests the missing sufficiency assumption separately: identical full source records can represent two histories with different expanded scheduler states. The user accepted a documented canonical expanded history for ambiguous late records on 2026-10-02. Exact equality with the unknowable actual history is waived for that domain; deterministic canonical selection, uninterrupted-reference comparison and restored futures remain required. Early taxi Saves retain their exact comparison requirements.

## Proposed expanded Save Snapshot, schema 2

Reserve record `schemaVersion: 2`; this is a specification, not admission by the current schema-1 loader. Retain record fields `identity`, `savedAt`, `where`, and `snapshot`. Identity remains Title `dion`, opening Destination `metis`, pinned STX/program SHA-256, and the **complete served expanded** `contentSha256`. Current physical Body is session state; TOLOSA arrival must not switch Destination or storage namespace. I3 owns the expanded content digest under [ADR 0065](../adr/0065-promote-bounded-dion-catalogue-content-through-an-explicit-export.md); no digest is invented before the actual served export exists.

Keep the current `snapshot: { remainder, snapshot: state }` envelope. `remainder` is a finite fractional browser tick in `[0, 1/50)` after normalization of the existing boundary epsilon. Existing taxi state is retained field for field, including pending input, passenger admission, reveal, card selection, taxi route/cursor/dwell/heights, doors, clock/cash, script/message, sound, driver/sign, sky and phase. Expand owners rather than treating `DionSnapshot`'s presentation-facing fields as a complete new save type. Names below are proposed semantic groups; the inventory gives their original readers/writers and units.

A browser call must expose a consistent snapshot. Prefer a synchronous `captureResume()` outside the atomic frame invocation: all zero-tick reentries and their input/interpreter order finish before that call returns. If I4 proves internal subpasses unobservable and captures cannot occur reentrantly, their local call-stack temporaries need no serialization. This does **not** waive the retained post-wait work, input mailbox, fractional tick or other live latches at a public capture point. If callbacks expose an internal subpass, serialize its exact continuation instead. The inventory conservatively retains uncertain state until first-frame and future comparisons prove reconstruction.

Reconstruct immutable geometry/control/script/parameter references from already verified expanded content, then derived workspaces, matrices, drawing lists and presentation buffers **before** the first restored frame. Rebuilding a workspace must replay no gameplay action, time, script, message, sound, admission, Body transfer or animation. Preserve a previously selected admission candidate unless independent comparison proves refreshing it cannot alter later B. Current I2's constructor performs a candidate scan; that is not proof for the expanded path. No original pointer is admitted merely because it falls within RAM; resolve semantic content references and permitted cursor boundaries.

## Source admission, storage and replacement transaction

The only migration source is the [audit's exact allowlisted schema-1 identity](mercenary-iii-tourcraft-taxi-migration.md). Validate with its pinned **source** documents and validator, before interpreting newly added fields or comparing against the expanded hash. Do not use a new schema-2 validator as evidence that the old nested state is valid. The source validator's permissive ranges also require explicit reachable-state/cross-field checks in the migration contract; an in-range value alone does not justify deterministic reconstruction. Preserve unknown properties only if deliberately allowed; reject attempts to smuggle schema-2 references through a schema-1 record.

Build and validate the candidate in isolation. Load and verify all expanded playable dependencies, migrate only under a proved mapping, validate its complete nested state, reconstruct presentation, then replace the active Gameplay Session in one commit. A failure at any stage leaves the active session and source bytes untouched. Foreign Title/Destination/program/content/schema and malformed nested records are refused with a path/reason. Tests must exercise the transaction, not just assert that a parser throws.

Continue using independent `DION_STORAGE.save(slot)` and `DION_STORAGE.resume` keys from the existing [codec](../../web/src/dion/save.ts) and [resume adapter](../../web/src/dion/resume.ts). A slot Load never overwrites the source slot. Session Resume migration must preserve the original record before any owner flush can replace it, and failed decoding must not allow a newly created session to erase it automatically. Inspect the current new-game fallback when implementing this: starting a fresh session after refusal is not evidence of source-preserving recovery. New Game remains an explicit shell action; it is not migration error handling. Retain Web Locks ownership and cooperative takeover, title isolation, and independent player Saves.

## Required independent browser comparisons

For each [33-control source row](mercenary-iii-tourcraft-taxi-migration.md), create source records by uninterrupted I2 inputs, never by constructing a fabricated snapshot. Separately replay those same inputs from expanded New Game without any restoration. At the chosen checkpoint migrate both a slot Save and Session Resume; immediately compare the entire Frame Description/raster at each existing Preset, full panel pixels, message cells and semantic state. Replay the identical later inputs and **compare every tick, ordered subpass transition, frame and event** through taxi completion, position-based TOURCRAFT entry, all 927 playback frames, first foot frame 928, and at least 600 further frames with immediate exterior movement. Held browser keys are supplied as later inputs; pending actions already in Session State stay in the record.

For ambiguous late source records, separately execute the documented canonical expanded reference without restoration. Identical validated source state must select that same reference regardless of `savedAt`, slot name or browser wall time. Compare the migrated first frame, full retained owners and identical-input futures against that reference using the same checks above. Include the two colliding histories from the ambiguity ledger: both must select the same canonical result, while the independent reference supplies the expected result rather than the migrator itself. Retain source-validation and replacement-failure tests. This canonical comparison does not weaken any of the 33 early controls.

Also run schema-2 Save and Session Resume at pre-B, unconsumed B, armed admission/start, launch, space/accelerated-rate changes, same-frame reentry 139, Body setup/462, descent/contact/883, recorded L/927 and on-foot 928. Add queued campaign dialogue, threshold-before-timer launch, clear-flag-before-return stack nesting, active/refused pilot start, busy/description continuation, timed countdown `1/0/FFFF/8000/7FFF`, timer overwrite, passive encounter override/departure/expiry, cabin look held through exit, day rollover and fractional tick immediately before an atomic frame. Reach ordinary states by actual browser inputs; label injected boundary controls separately.

Refusal rows cover changed served dependency bytes; wrong identity/schema; malformed nested arrays; invalid record/control/script/trajectory cursor; contradictory Body/context/Occupancy; duplicate residences/doors; out-of-range clock fractions; unsupported campaign flags; and malformed signed timer targets. Assert that active session, all source bytes, other slots and every other Title's records remain unchanged. Cover failure after parse but before candidate commit and failure during presentation reconstruction. The first restored frame cannot be skipped to hide a transient mismatch.

Production-browser acceptance includes keyboard taxi approach/TOURCRAFT B, cabin looking, automatic exit, mid-flight Save/Load, page reload Session Resume, migration from all retained source checkpoints, ownership takeover and refusal without destructive flush. Original-machine research below informs these tests; it cannot replace them. Schema-2 runtime does not yet exist in this research work, so no expanded browser comparison is reported as passed.

## Completion boundary

The versioned schema and transaction above are an implementation contract with explicitly remaining proofs. The inventory distinguishes verified immutable data from retained mutable owners; the migration audit pins current source admission and identifies a concrete D2 failure. Original-machine comparisons remain finite research evidence. ADR 0068 accepts both the late-source expanded-history priority and the documented canonical reference for ambiguous late records. Defining and proving that deterministic reconstruction, proving allowed early-source initialization, and completing expanded browser codec/future tests remain implementation tasks. The reference-history policy decision is resolved. No taxi record is rewritten, no new playable content is exported, and no Save-format compatibility with the original on-disk game is proposed.
