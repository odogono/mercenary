## Scheduler, overwriteable queue and signed timer

Every original loop top calls `$5A3D0` before input and before the interpreter. Its order is consequential:

1. With flag 9 clear, signed seconds ≥ 32,400 attempts election `$77`. With flag 9 set, signed seconds ≥ 61,200 attempts mining `$13`. The original compares the seconds field, not a combined day/seconds deadline. Availability consumption prevents repeating an already launched threshold script across continued waiting or subsequent days.
2. Then, if timed target `$7280` is nonzero, signed countdown `$727E` is negative and flag 6 is clear, clear the target and launch its **bank offset** directly through `$55A3C`. A threshold launch in step 1 can set flag 6 and defer this launch. Message busy state is not tested here: a due continuation can become active while a message is busy, and its first instruction waits for the interpreter's busy guard.
3. Input can independently attempt script launch. The interpreter `$52860` then returns if message busy `$723A` is nonzero; otherwise it resumes continuing message `$7230` before handling any queued script. With no continuation, it checks queue `$711C`; `$55A0E` retains it while flag 6 is set, but clears it before the ordinary availability lookup when inactive. A now-unavailable queued ID is consumed and refused.
4. Finally, fetch/execute one opcode from the current PC. A queued launch can execute its first instruction in that invocation. The accepted transition subpasses repeat this recovered loop order without delivering another tick.

Ordinary `$55A1A` first refuses availability bit 7 clear. If flag 6 is set, bit 5 chooses queue or refusal; queuing unconditionally replaces the single `$711C` word and does not yet consume availability. When inactive, bit 6 preserves repeatability; otherwise bit 7 is consumed. Both ordinary and direct-offset starts push the current PC on the existing downward-growing stack and set flag 6. Direct-offset starts bypass the availability table entirely. They do not clear the queued ID. Because `Close` clears flag 6 one invocation before its return, a threshold or timed launch can nest at this precise boundary; retain the old stack rather than reconstructing an empty one.

Opcode `$26` writes both timed words immediately: unsigned countdown bits and bank offset. There is one slot, so a later writer replaces an earlier continuation. Each **unpaused** VBL increments unsigned wait `$7236` and decrements timer `$727E` modulo 65,536 even when the target is zero. Timer zero is not due; the next decrement yields `$FFFF` and is due. If active dialogue blocks dispatch through the entire negative half-cycle, decrement from `$8000` yields `$7FFF`; dispatch is then blocked until the timer becomes negative again. A clamped countdown, absolute deadline, script-number target or FIFO would change the original futures. Pause stops these increments/decrements; script waits and message holds do not count accelerated game seconds.

The sign/wrap rule is recovered scheduler semantics, not a claimed normal default outcome. Each added routine has at most six one-row packed holds (201 ticks each), three blank holds (51 ticks each), one W150 and fewer than 40 nonwaiting instruction invocations. A conservative active-execution bound per routine is below 2,000 unpaused ticks; all five stages together are below 10,000. Scheduled idle delays of 1,500/750/750 ticks are separate from those active-execution bounds. The ordinary pilot ends at frame 745 (8,195 ticks), and pause freezes the timer. These finite admitted scripts do not explain a 32,768-tick active deferral; any wrap probe is a synthetic boundary control. Additional indefinite active scripts or foreign campaign states would require a new reachability assessment.

The normal 9 h → 17 h threshold separation is 28,800 game seconds; the complete accepted early atomic flight advances 13,832. A synthetic jump from pre-election seconds directly to 62,000 during active flight stresses precedence and queue/timer interaction, but does not establish that both thresholds naturally overlap within this normal flight. Current `DionAction` exposes only activate/star/plus/minus/board/leave and uses fixed opening clock step/refill; it provides no original clock-rate menu. This handoff admits no foreign rate configuration.

Important cases for implementation/regression are unavailable-before-busy refusal; repeated queue writes without availability consumption; replacement by a different queueable ID; unavailable queued pickup; busy and continuation-message precedence; due timer with busy message but inactive script; active-script deferral across sign/wrap; timer overwrite by a later script; threshold-before-timer precedence; and launch between `Close`'s flag clear and return. The two threshold scripts and their direct-offset continuations must use these common rules rather than separate authored event deadlines.
