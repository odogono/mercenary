# Spec: Extracted game typefaces

## Objective

Give the Browser Shell faithful, selectable typography without checking source media or
laboratory evidence into Git — the generated faces themselves travel in the tracked Data
Payload (ADR 0029). The current _Escape from Targ_ page defaults to the Reference Build's C64
gameplay face; a reader may choose the Working Authority's small Damocles interface face, and
that choice survives reloads. Success means both faces are reproducibly regenerated from
verified laboratory evidence, every generated byte lands in the Data Payload, and visible shell
text never silently falls back to an unrelated system face.

The feature covers user-visible DOM text in the main Browser Shell. It does not redraw text in
the WebGL Game Surface, reproduce either title logo, or advance Damocles gameplay work.

## Technology and commands

- Python 3.13 or newer.
- `fonttools[woff]==4.63.0`, `Brotli==1.2.0`, and `Pillow==12.3.0`, installed in
  `research/typography/.venv` from the pinned requirements document.
- Environment setup:
  `python3 -m venv research/typography/.venv && research/typography/.venv/bin/python -m pip install -r research/typography/requirements.txt`.
- Export:
  `research/typography/export --mercenary-run research/c64-reference-build/work/<interactive-run> --damocles-run-a research/damocles-st/work/<first-run> --damocles-run-b research/damocles-st/work/<second-run> --payload payload`.
- Typography tests:
  `research/typography/.venv/bin/python -m unittest discover -s research/typography/tests -v`.
- Existing laboratory tests:
  `research/c64-reference-build/.venv/bin/python -m unittest discover -s research/c64-reference-build/tests -v`
  and
  `python3 -m unittest discover -s research/damocles-st/tests -v`.
- Browser verification:
  `cd web && bun test && bun run typecheck && bun run lint && bun run format:check && bun run test:e2e`.
- Local page: `cd web && bun run dev`.

## Project structure

- `research/typography/` owns cross-title source validation, glyph extraction, synthesized
  additions, OpenType contour construction, and deterministic export tests.
- `payload/fonts/` receives the two WOFF2 files; `payload/typography.json` carries the
  runtime contract and provenance. `payload/typography-review.png` shows both complete faces
  for human review, while `payload/typography-review-damocles.png` provides a dedicated
  Damocles sheet. The existing payload manifest records all generated artifact hashes.
- `web/src/shell/typography.ts` validates the runtime contract, verifies font bytes, registers
  the faces, and owns the persisted choice.
- `web/index.html` contains the small accessible selector and the CSS that applies the selected
  face to Browser Shell text.

## Code style

Research boundaries fail with specific `TypographyError` messages rather than assertions or
partial output. Runtime values are narrowed before use and face IDs are a closed vocabulary:

```ts
export type TypefaceId = "mercenary" | "damocles";

export const applyTypeface = (root: HTMLElement, face: TypefaceId): void => {
  root.dataset["fontFace"] = face;
};
```

Python uses typed, pure transformations for bitmap and contour work; filesystem writes happen
only after every input and generated document has validated. Tests describe outcomes and use
temporary directories rather than repository payload files.

## Data and rendering contract

`typography.json` has schema version 1, a `mercenary` default, and exactly two faces. Each face
names its stable ID, CSS family, relative WOFF2 path, SHA-256, extracted glyph count, and
synthesized glyph count. Paths are fixed to `fonts/mercenary.woff2` and
`fonts/damocles.woff2`.

Mercenary reads exactly `$7800-$7FFF` from verified conditioned physical RAM. For each of two
independent cold Damocles runs, the exporter assembles a canonical character sheet from known
clean cells of the black first-world cockpit face; the two logical pixel sheets and their
monospaced advances must agree before export. The six-pixel Damocles advance is derived from
the observed positions of consecutive full-width glyphs in the `ERIS` and `EMPTY` labels,
rather than assigned by the font builder. Coloured condensed panel labels are not mixed
into that source face. Mercenary RAM slots `$21-$3A` and `$1F` are not classified as lowercase
or question-mark source glyphs: the former carry repeated non-text leading rows and the latter
carries an unrelated trailing row. Lowercase and `?` are therefore synthesized and reported as
such rather than silently repairing extracted pixels. Synthesized lowercase uses independently
authored lowercase forms rather than uppercase aliases. Source glyphs retain their pixels and advance. Printable ASCII plus
`U+00B0`, `U+00B7`, `U+2014`, and `U+2026` is complete in each face; absent source characters
are independently authored on the same grid and counted as synthesized.

Each lit source pixel becomes one grid-aligned square contour. Fonts are regular, unhinted,
and carry deterministic timestamps and table order. Each face is baseline-aligned to its own
logical bitmap height, and its declared cap height matches that outline grid. At runtime both byte streams are fetched,
SHA-256 checked, registered through `FontFace`, and awaited before the Gameplay Session becomes
ready. Missing, malformed, corrupt, or unloadable typography is a visible startup failure.

The selector defaults to Mercenary, stores only `mercenary` or `damocles` under the versioned
key `mercenary.browser-shell.typeface.v1`, and ignores invalid or inaccessible storage. A
focused form control owns its keys; the Control Profile must not interpret its arrows as
Movement Intent.

## Testing strategy

- Small Python tests prove the 2,048-byte C64 boundary, semantic character mapping, Damocles
  sheet agreement, synthesized repertoire, bitmap/outline round trips, and deterministic
  output metadata.
- Browser unit tests prove schema validation, path allow-listing, byte hashes, font
  registration, default selection, persistence, and hostile storage behavior.
- Server tests prove only the two declared WOFF2 paths are served with `font/woff2`.
- Chromium E2E proves both faces load, switching changes the applied family, reload restores
  the choice, focused selector arrows do not move the player, and the shell does not overflow
  at 320, 768, 1024, or 1440 CSS pixels.
- The `payload/typography-review.png` sheet shows both faces at integer scale in
  `CHARACTER_REPERTOIRE` order. Blue cell borders identify extracted glyphs and orange borders
  identify synthesized glyphs; it is human-review evidence, not an authoritative tracked
  screenshot. `payload/typography-review-damocles.png` uses the same order and legend for the
  Damocles face alone.

## Boundaries

- Always validate both laboratories' complete run manifests and every registered artifact hash
  before reading source bytes. Damocles captures must have distinct run IDs and both source
  scenarios must match their registered tracked digests; distinguish Reference Build facts from
  Working-Authority Evidence.
- Always write extracted sheets, normalized glyph data, WOFF2, and review images only beneath
  `payload/`, laboratory `work/`, or `restricted/` storage; the latter two remain ignored.
- The public typography export command accepts only this repository's `payload/` root;
  tests replace that root through an internal fixture seam rather than weakening the CLI boundary.
- Ask before changing the supported source builds, the two-face vocabulary, the required
  character repertoire, pinned font toolchain, or public-distribution posture.
- Never track ROM-derived bitmap rows, font binaries, RAM, screenshots, or glyph sheets.
- Never treat this typography exception as permission to load any other Damocles data or build
  its Game Surface before the sequencing decision changes.

## Success criteria

1. One command reproducibly emits two valid WOFF2 files and schema-valid metadata from verified
   inputs, with equal hashes on repeated runs.
2. Every extracted outline round-trips to its source logical bitmap, and both faces cover the
   declared Unicode repertoire without browser fallback.
3. The main Browser Shell starts only after both verified faces load, defaults to Mercenary,
   and persists an accessible Damocles selection.
4. Selector interaction cannot produce Movement Intent, and the responsive shell remains
   usable at every supported width.
5. All research, web, static, and E2E checks pass while laboratory `work/` and `restricted/`
   storage keeps everything the Data Payload does not carry.
