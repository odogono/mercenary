# Admit one development console that writes play

The Browser Shell gains a Shell Console whose commands write gameplay state — teleporting to a cell or a Room, restoring a Save — through the Gameplay Session's own actions and the preference and Save cores, never around them. It is admitted as a development tool rather than as play: it reaches what no player action can, so a session it has touched is no longer reproducible from its inputs, and it is therefore never part of a trace. ADR 0018 leaves the existing diagnostics alone because they touch no gameplay state; this one does, so it is named here rather than assumed under that exemption.

The console is the only Browser Shell surface that writes play — every other is presentation-only — and the separation from traces is structural rather than enforced at runtime: replay runs on its own page, no recorder exists, and a test holds the console's vocabulary and the trace decoder's apart so the day a recorder arrives is the day it fails. Because the session validates neither `place` nor `teleport`, refusing unusable input is the console's own work: a cell off the world, a Room the payload lacks, or Room zero — which names the surface rather than a Room — are declined with the reason, and a Room is entered by teleporting alone so the session's own containment decides where the player lands.
