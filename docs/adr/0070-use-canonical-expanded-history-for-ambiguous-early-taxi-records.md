# Use canonical expanded history for ambiguous early taxi records

> **Superseded by [ADR 0073](0073-drop-pre-release-prototype-save-migration.md), accepted 2026-10-03:** old browser-prototype Save migration is no longer required. The following records the earlier decision.

Accepted by the user, 2026-10-03, for [D2](../research/mercenary-iii-tourcraft-milestone-review.md#new-early-compatibility-failure-returned-to-d2), [R8a/#735](https://github.com/odogono/mercenary/issues/735) and I4/#711. This extends [ADR 0068](0068-reconcile-known-taxi-saves-with-expanded-campaign-history.md): canonical expanded history is permitted for ambiguous **early** I2 Save and Session Resume records as well as late ones. The [ordinary early cursor collision](../research/mercenary-iii-tourcraft-source-eligibility.md#ordinary-early-cursor-collision-returned-to-d2) proves that identical complete old records can have different future-affecting face cursors even after output rebuilding; a source-only constructor cannot recover both actual histories.

Where all matching supported histories determine the same retained expanded owners and observables, migration must preserve that exact expanded meaning. Where they disagree, migration must select a documented deterministic canonical history that reproduces the complete validated old source, independently of wall time and storage metadata. Its constructed owners, first restored frame/panel and identical-input futures must match independent uninterrupted expanded execution of that selected reference. Equality with the unknowable actual history is waived only for the ambiguous domain; owner serialization and the rebuild-before-read proofs remain required.

All 33 taxi controls remain required. R8a must classify each complete source by its matching history class, retaining its actual input witness: exact sources keep their exact preservation and expanded-future comparisons; ambiguous sources get an explicitly documented canonical reference and the same full first-frame/owner/future checks against that reference. A checkpoint name, one replay or current equality of a few owners is not proof that its whole source class is exact. No control is silently omitted or relabeled exact.

The allowlisted identity, full source validation, preservation of original source bytes, isolated candidate validation and independent Title-local Save/Session Resume ownership remain required. ADR 0068's late campaign priority and exclusions remain in force. This decision changes the early reference policy, not the reconstruction algorithm: #735 still owes complete eligibility/classification and independent canonical-reference proofs, #736 owes output rebuild proofs, #737 constructs all expanded owners, and #711 implements and verifies migration in the browser. Accepting this policy does not certify the existing finite comparators or a general solver.
