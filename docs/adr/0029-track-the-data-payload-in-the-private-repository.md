# Track the Data Payload in the private repository

The Data Payload in `/payload/` and the Golden Traces in `/traces/` are tracked. This amends
ADR 0014's single publication hedge — "extracted game data lives in one gitignored Data
Payload" — and the clause of ADR 0019 that gitignores traces and any built bundle alike as
payload-derived, keeping the second half of both: engine code is still written from
understanding rather than mechanically translated, and every byte entering the payload is still
re-extracted from our own Reference Build by our own tooling. The Independent Implementation
boundary of ADR 0014 and ADR 0002 is untouched; only the storage location changes. ADR 0021's
statement that the Damocles interface typeface's generated bytes remain ignored Restricted
Material is superseded on that point alone: those bytes land in `payload/fonts/` and are now
tracked with the rest of the payload, while everything else that ADR says about scope stands.

Worktrees forced the decision. A `git worktree` is the unit of work here, and an ignored payload
means a fresh one has no working test suite: it must be hand-populated, or the frozen Swift Trace
Oracle must be run out of `trace-oracle-last-good` to regenerate the traces before a single
Replay Gate can be believed. That is a per-worktree tax on the everyday case to protect a
publication door that is no longer opened this way. Tracking also improves the evidence: the
payload manifest is sorted keys, content hashes and no timestamps, so it does not churn; a
divergence in a Golden Trace becomes a reviewable diff rather than a re-run against a recording
that has already been replaced; and `expectRecordedPayload` — which makes every gate assert it
graded against the extraction its trace was recorded from — is a stronger claim when the payload
it names is in the same commit as the trace.

What holds this up is ADR 0017 and the publication policy, not the ignore rule. This repository
and its history are permanently private and are not a candidate for a public source release; a
public version of the app is a separate repository built fresh, never an export of this history.
That discipline, and the qualified-review clearance gate of ADR 0004, are what decide whether
game data may be published — an ignored path never did, it only reduced accidental disclosure.
`/roms/` and `/restricted/` stay outside Git, as do the laboratory `work/` trees and any built
web bundle: supplied media, raw evidence and a distribution are separate questions from where
our own extraction lives.

The alternative — tracking the payload but not the traces — was rejected as half a fix, since a
worktree without traces still cannot run a gate. The accepted costs: eleven megabytes of JSONL
enter the history, a trace regeneration lands as a large diff that must be reviewed as a
deliberate re-recording rather than skimmed, and the future-publication door is now held open
solely by the separate-repository discipline, which is a promise about process rather than a
property of the checkout.
