# Place authored content on the surface and react to it through Surface Regions

Accepted, 2026-10-30. Targ gains its first Authored Asset placed in the world: the Shrine, a fixed object at Surface Cell (20,20), outside the 16×16 city, with a Talk Script that reacts when the player arrives and when an object is left inside it. It exercises [ADR 0081](0081-share-one-geometry-asset-format-and-edit-it-in-blender.md)'s Blender path and [ADR 0080](0080-run-targs-scripts-as-talk-scripts.md)'s Talk Scripts end to end, and it ships in normal play: it is out of the way and changes no existing outcome.

## Decision

- **Authored placements are tracked beside the payload.** The Data Payload stays pure extractor output. The Authored Asset's own Sidecar placements (`assets/targ/objects/authored-shrine.json`) place it as an object instance in slot 64, after the original 64, as the original places its own out-of-city building (slot 61, at cell (81,35)) as a fixed object rather than a Surface Structure. Object placement already covers any surface position, distant drawing and Saves; the 16×16 Surface Structure cell table does not reach (20,20). A Save made before an Authored object was placed has no word of it, and restores with the object where its placement put it.
- **Surface Regions are play data, and a building carries its own.** A Surface Region is a named area of the surface the Gameplay Session tracks. A building's region is its footprint: its Sidecar placement names it (`"region": "shrine"`), and the region is the extent of the placed geometry. An area that is no building's, such as the Shrine's grounds, is a table in the Gameplay Session (`web/src/session/surfaceRegions.ts`). This follows Damocles, whose Location Triggers key on the regions of the structure the player is in.
- **A region is a Host Object its Talk Script owns.** A Talk Script names the region it owns (`owns` in `web/src/talk/scripts.ts`), and the Talk host makes the region a NorthTalk Host Object with that script as its Owning Script. What happens in the region is delivered to that object, not broadcast: the player's arrival in each region entered as `arrived`, and an object left there as `received item`, to the innermost region holding it, as a MUD tells the room a thing is dropped in. The script needs no Guard naming its place, and a new place adds a script rather than a branch to an existing Handler. A region no script owns hears nothing. `dropped object` is still broadcast to every script, so a script may answer a drop anywhere, as deliveries do.
- **One script answers for a whole place, along the Message Path.** A NorthTalk script owns at most one Host Object, so a script also names the regions it `hears`: the host makes each one a child of the owned region, and their messages climb to it. The Shrine's script owns its footprint and hears its grounds; `the target` tells it which was told. Deeper nesting, and `pass` up to an enclosing place, come the same way when a place needs them.
- **The city ends at its grid.** The view had repeated the 16×16 city across the whole surface, so (20,20) drew a copy of cell (4,4). Nothing in the evidence supports that, and Targ outside cells 0–15 is open ground; the repeat is removed, so the Shrine stands alone.
- **Comparisons see no authored content.** Golden Traces and comparisons with the original load the Data Payload without `assets/targ/`, so the Shrine's slot is absent on both sides; the Surface Regions see nothing to compare outside the city.

Rejected: a new cell in the payload's surface table (breaks the payload's purity and the 16×16 grid); regions as marker parts in Blender (couples play to a model edit; the placement names the region and the geometry gives its extent); a broadcast `arrived region` and a `within(region)` query, which each script narrows with Guards (every new place grows a shared Handler's conditions).

## Consequences

- An authored object slot must not collide with an original one, which the asset loader refuses, and Saves already store slots as bytes.
- The energy crystal, once offered at the Shrine, is fixed and can no longer be sold. That is the player's choice. The World Port gains `fixed`, so the Shrine reads its peace from the world rather than from a Script Variable of its own.
- A script that hears several regions checks `the target` where they overlap, as the Shrine does: arriving in its footprint was already told by its grounds, and a drop in the grounds alone is no concern of the Shrine's.
