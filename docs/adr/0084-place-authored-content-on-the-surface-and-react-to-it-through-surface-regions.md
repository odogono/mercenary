# Place authored content on the surface and react to it through Surface Regions

Accepted, 2026-10-30. Targ gains its first Authored Asset placed in the world: the Shrine, a fixed object at Surface Cell (20,20), outside the 16×16 city, with a Talk Script that reacts when the player arrives and when an object is left inside it. It exercises [ADR 0081](0081-share-one-geometry-asset-format-and-edit-it-in-blender.md)'s Blender path and [ADR 0080](0080-run-targs-scripts-as-talk-scripts.md)'s Talk Scripts end to end, and it ships in normal play: it is out of the way and changes no existing outcome.

## Decision

- **Authored placements are tracked beside the payload.** The Data Payload stays pure extractor output. The Authored Asset's own Sidecar placements (`assets/targ/objects/authored-shrine.json`) place it as an object instance in slot 64, after the original 64, as the original places its own out-of-city building (slot 61, at cell (81,35)) as a fixed object rather than a Surface Structure. Object placement already covers any surface position, distant drawing and Saves; the 16×16 Surface Structure cell table does not reach (20,20). A Save made before an Authored object was placed has no word of it, and restores with the object where its placement put it.
- **A building carries its Surface Region, and names the Talk Script that answers for it.** Its Sidecar placement says `"region": { "name": "shrine", "script": "shrine", "approach": 28672 }`. The region is the building's placed extent, height included, so flying high over it is not visiting it; its approach is that extent grown by `approach` on every side but below. As a Damocles structure carries its own location table, a new place is one asset and one `.talk` file, with nothing to register elsewhere. A placement naming a Talk Script the game doesn't have is refused when the Talk Scripts load, and two regions may not share a name or a script.
- **What happens at a region goes to its Talk Script alone.** The Talk host makes each region a NorthTalk Host Object, owned by the script its placement names, and delivers to it rather than broadcasting: the player's `approached`, `arrived`, `departed` and `withdrew`, and an object that comes to lie inside as `received item` or stops as `lost item`. The script needs no Guard naming its place. The object's id is the script's name, so a Save still finds it after the region is renamed. `dropped object` is still broadcast to every script, so a script may answer a drop anywhere, as deliveries do.
- **One region per script, side by side.** A NorthTalk script owns at most one Host Object, and a building has one region with its approach, so a building has one script. When a place inside another needs to hand on what it doesn't answer, regions get parents and scripts use `pass`, along NorthTalk's Message Path.
- **The city ends at its grid.** The view had repeated the 16×16 city across the whole surface, so (20,20) drew a copy of cell (4,4). Nothing in the evidence supports that, and Targ outside cells 0–15 is open ground; the repeat is removed, so the Shrine stands alone.
- **Comparisons see no authored content.** Golden Traces and comparisons with the original load the Data Payload without `assets/targ/`, so the Shrine's slot is absent on both sides; the Surface Regions see nothing to compare outside the city.

Rejected: a new cell in the payload's surface table (breaks the payload's purity and the 16×16 grid); regions as marker parts in Blender (couples play to a model edit; the placement names the region and the geometry gives its extent); a broadcast `arrived region` and a `within(region)` query, which each script narrows with Guards (every new place grows a shared Handler's conditions); a separate region for the ground around a building, whose messages climb to the building's script (the script must then ask `the target` where the two overlap, where an approach margin says 'near' without a second region); regions listed in the Talk Scripts' own table (two names that must agree, with nothing checking them).

## Consequences

- An authored object slot must not collide with an original one, which the asset loader refuses, and Saves already store slots as bytes.
- The energy crystal, once offered at the Shrine, is fixed and can no longer be sold. That is the player's choice. The World Port gains `fixed`, so the Shrine reads its peace from the world rather than from a Script Variable.
